三、三層去留建議

🟢 核心保留 — 工作坊脊柱 · 5 個檔 · 720 MB

少了任何一個,流程就斷。這就是要打包、要進 git、要帶去同濟的那一份。

  • 乡镇街道邊界(229)— 選基地
  • AI 影像解譯-帶高度(1,366,427,Height 0–338 m)— 幾何 + 實測高度
  • 開源建設用地 EULUC(55,018)— 判定「誰的」主鍵
  • 帶年份-內測版(462,478,Function/Age)— 第②源 + 年代
  • 百度 AOI(25,680,結構/價格/時間)— 第③源

🟡 潛力保留 — 尚未接入工作坊,但價值高、值得留

  • POI(留「一個」年份) — 全市 24 類興趣點。這是 Part-1「讀資料」階梯最標準的「上萬個點 → 分類 → 聚類」素材,也能反向精修 stakeholder 級聯(政府機構 50,862 → state;商務住宅 42,766 → developer/resident)。建議留最新的 26(14 GB,最完整)或精簡留 21(僅 152 MB),其餘 6 個年份清掉。typology / generative 線已在用它。
  • 社區邊界(5,596,38 MB)— 比街道更細一級,讓未來工作坊能下沉到「居委會」尺度。便宜,先留。
  • 年代 Age 欄位(已含在核心的帶年份檔)— 可驅動「vintage / 時間」透鏡,呼應 typology v06「鏡頭有年份」的主張。
  • 路網分類圖層子集(主幹道 / 市區一級)— 街道與「公共地面」語境;若不確定先留分類子集,清掉 4 GB 的合集與設施。
  • landuse-webmap(25,845,12 MB)、市區兩級 2026(16 區)— 交叉驗證 / 參考框,極便宜,留著無妨。
為什麼不直接全留:POI 七個年份就佔 34 GB,內容大量重疊。留一個年份即可拿到全部教學價值。

🔴 建議清除 — 死重量 / 重複 / 非工作坊

  • 百度建築 v1 + v2(802 MB)— 全庫 0 處引用,已被 AI 帶高度版取代。
  • AI 影像解譯 / AI 電子解譯(無高度版)(~2 GB 含附屬檔)— 0 處引用,與帶高度版幾何重複。
  • 帶 type 建築(26 MB)— 0 引用。
  • POI 重複年份(留 1 清 6)— 視保留哪年,省下 20–34 GB。
  • 開源土地利用柵格 1m/10m/30m(19 GB)— 工作坊用的是 EULUC 向量版,不用柵格。(僅其他研究線用,確認後再清)
  • 交通設施(343 MB)、市區兩級舊審圖版 / 駐地(~1 MB)— 未用。
精簡後體積: 從 61 GB 降到 —— 精簡版(POI 留 21)約 < 2 GB;保守版(POI 留 26 + 路網子集)約 16–19 GB。光是清掉「0 引用死重量 + 柵格 + 重複 POI 年份」就回收 40–59 GB。

四、誠實前提(務必隨資料一起說明)

① informal 恆空。本資料沒有「非正式 / 自建」的真實訊號,該類保留但永遠為空 —— 不從形態硬猜身份(不捏造)。
② AI 高度天花板。實測高度對極端超高層(> ~340 m)可能低估、被截斷;最高值止於 338 m。
③ AOI 價格 / 結構是商業代理。僅作離散 tag 用,不外發原值。
④ EULUC 為地塊(面)級,優先於建築級 Function。故居住地塊內零星公建會被併入居住 —— 是簡化,不是產權考證。「誰的權利」= 用途的離散級聯查表。

五、建議動作(可勾選)

  • 把 🟢 核心 5 檔(720 MB)獨立打包成 workshop_data/,進 git;這是流程唯一硬相依。
  • POI 決定保留哪一個年份(精簡選 21 / 完整選 26),其餘年份移出或封存。
  • 清掉 0 引用死重量:百度建築、AI 無高度兩版、帶 type(回收 ~2 GB)。
  • 確認 typology / generative 線是否仍需柵格土地利用 19 GB;工作坊不需,可移到冷儲存。
  • 社區邊界 / landuse-webmap / 市區 2026 體積小,先留作潛力,不急著動。
  • 把本頁的「誠實前提」四點貼進工作坊講義 —— 資料的界線本身就是教學內容。
